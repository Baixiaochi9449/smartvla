\hypertarget{method}{%
\section{SmartVLA Framework}\label{method}}

SmartVLA builds on pretrained representations to strengthen instruction-conditioned control while
retaining complete-task execution. Our core idea is to refine the granularity of instruction--action
supervision by explicitly pairing local instructions with their corresponding action segments while
retaining the original task-level supervision. For data construction, we use automated annotation to
establish these instruction--action pairs for supervision
(Section~\ref{steering-oriented-data-construction}). For training, we adopt a staged procedure to
encourage the policy to learn and use this correspondence while preserving complete-task supervision
(Section~\ref{steering-centric-policy-training}).

\hypertarget{steering-oriented-data-construction}{%
\subsection{Action-Aligned Data Construction Pipeline}\label{steering-oriented-data-construction}}

We represent local supervision as
\[
r_i=(\mathbf O_i,\mathbf S_i,\mathbf A_i,c_i,z_i,g_i),
\]
where observations, robot states, and actions span a segment of length $L_i$, while $c_i$, $z_i$,
and $g_i$ denote the segment's instruction, object/target evidence, and interaction grade,
respectively.

To construct this segment-level supervision, we organize the conversion from raw demonstrations to
training examples into seven interconnected stages. Figure~\ref{fig:dataset-construction}(a)
illustrates the automated annotation pipeline.

\begin{enumerate}
\setlength{\itemsep}{0pt}
\setlength{\parsep}{0pt}
\item \textbf{Quality filtering and representation unification.} We filter trajectories from multiple
sources to remove samples with missing language annotations, unusable visual observations, or
anomalous states or actions. We then unify the representations of observations, robot states, and
actions and record the valid dimensions for each robot configuration, providing a common interface
across data sources while preserving their valid control information.

\item \textbf{Candidate boundary generation.} We generate candidate boundaries from differences
between consecutive actions, motion curvature, gripper opening and closing events, and cross-frame
visual changes. DINOv3 is used to represent cross-frame visual changes. Temporal smoothing and the
merging of excessively short segments reduce oversegmentation caused by transient fluctuations,
yielding candidate control segments.

\item \textbf{Object and interaction evidence extraction.} We use GroundingDINO to localize
candidate objects and SAM to obtain object or target-region masks. Temporal tracking associates
object positions across consecutive frames. We then combine gripper--object relative positions,
object motion, gripper state, and contact evidence to infer the active object, target region, and
interaction phase.

\item \textbf{Segment refinement and interaction grading.} We combine candidate boundaries with
interaction evidence and refine segment boundaries using temporal consistency and task-family
rules. Each segment is assigned a local behavioral scope and a Low, Mid, or High interaction grade.
The resulting structured records contain action segments, control phases, object roles, and spatial
evidence, providing a basis for subsequent instruction generation.

\item \textbf{Grade-conditioned instruction rewriting.} We select applicable rewrite families
according to the interaction grade and use Qwen to generate candidate local instructions from the
original task and structured segment records. We also construct visual-prompt training examples for
applicable segments. Candidate instructions and visual prompts are associated with their
corresponding demonstration action segments; the applicability rules are described below and
summarized in Table~\ref{tab:grade-policies}.

\item \textbf{Sampling metadata recording.} For each candidate rewrite, we record the task type,
control phase, rewrite family, applicability conditions, and recommended sampling weight. This
metadata supports the subsequent organization of training examples by supervision type and scope
of applicability.

\item \textbf{Multimodal consistency review.} Using keyframes, candidate instructions, and spatial
annotations, we check consistency among instruction meaning, visual targets, and segment behavior.
We add alternative expressions where supported by the evidence and remove or disable language and
spatial labels that are inconsistent with the action scope, object relations, or visual target.
\end{enumerate}

This pipeline first establishes the local action scope and interaction context from demonstration
evidence, then performs constrained instruction generation, without requiring the language
generation model to independently infer the entire temporal structure from a complete video.

\textbf{Grade-conditioned rewriting rules.} In the fifth stage, interaction evidence constrains
the applicable rewrite families so that instruction content remains consistent with the local
behavioral scope of the corresponding segment. We use three rewrite families: Object-free atomic
motion, which describes local motion using instructions without object names; Synonym/task rewrite,
which varies the wording while preserving the local goal and execution scope; and Spatial visual
generalization, which pairs visual prompts such as points, boxes, regions, or trajectories in the
observation images with the corresponding local instructions and action segments. Visual prompts
are provided to the policy as part of the image observations, while action supervision comes from
the same demonstration segment.

For different phases of a task, we define rewriting strategies conditioned on three grades: Low
($g_0$), Mid ($g_1$), and High ($g_2$). These grades correspond to free-space motion, transitions,
and explicit object interaction, respectively. Low permits only atomic-motion and synonym/task
rewrites, avoiding spatial references when no clear interaction target is available; Mid permits all
three rewrite families; and High permits only synonym/task rewrites and spatial visual
generalization, avoiding the reduction of explicit object interactions to atomic motions that omit
essential object relations. For example, ``move up'' does not require identifying an object, whereas
a placement instruction must retain information about both the object to be placed and its target
location. Interaction grades therefore govern rewrite applicability and specificity, rather than
serving as a criterion for segment filtering. Figure~\ref{fig:dataset-construction}(c) illustrates
an example.

\par
\endgroup

\textbf{Final supervision format.} Through this pipeline, each local instruction is associated with
the corresponding observations, robot states, and demonstration action segment, forming the local
supervision dataset $\mathcal D_{\mathrm{local}}$. The same action segment can yield multiple
training examples through different applicable rewrites, while its action supervision continues to
come from the corresponding demonstration. We also retain complete trajectories and their original
task instructions to form the task-level supervision dataset $\mathcal D_{\mathrm{task}}$,
providing complementary supervision for local instruction following and complete-task execution.
Data composition and segmentation statistics are shown in Figure~\ref{fig:dataset-construction};
implementation details and segment-level examples are provided in
Appendix~\ref{appendix:data-construction}.

\hypertarget{steering-centric-policy-training}{%
\subsection{Three-Stage Training Recipe}\label{steering-centric-policy-training}}

We separate learning how instructions specify motion, how observations locate its target, and how
both transfer to a target domain. Let $\theta=(\psi,\phi)$ collect
the backbone and action-head parameters. The policy predicts $\mathbf A_t=\mathbf
a_{t:t+H-1}\sim\pi_\theta(\cdot\mid\mathbf o_t,\mathbf s_t,c_t)$; prediction length $H$ is distinct
from segment length $L_i$. All stages retain the native per-example action loss
$\ell_{\mathrm{act}}$, with objective
\begin{equation}
\label{eq:action-objective}
\mathcal L_{\mathrm{act}}(\theta;\mathcal D)=
\mathbb E_{(\mathbf o,\mathbf s,c,\mathbf A)\sim\mathcal D}
\left[\ell_{\mathrm{act}}(\theta;\mathbf o,\mathbf s,c,\mathbf A)\right].
\end{equation}

\textbf{Warmup: learn motion correspondence without image-based shortcuts.} Atomic instructions
specify motion without requiring object localization. Warmup therefore receives only atomic
instructions and robot state, freezes the backbone at $\psi_0$, and trains the action head with
$\mathcal L_{\mathrm w}(\phi)=\mathcal L_{\mathrm{act}}((\psi_0,\phi);\mathcal
D_{\mathrm{atomic}})$. Here $\mathcal D_{\mathrm{atomic}}$ contains eligible Low/Mid segments with
no image input. Different atomic commands specify corresponding motion patterns, while robot state
supplies the physical conditions for execution. Removing images prevents initial learning from
directly relying on visual scene cues; freezing the backbone focuses optimization on how the action
head uses existing representations, establishing a language-conditioned action prior for subsequent
visually conditioned learning.

\textbf{Pretraining: ground the prior in current scenes.} Motion alone does not identify its target:
``lift the object in the red box'' also requires binding the prompt to the current object. Starting
from warmup, we restore multi-view images and train both modules with $\mathcal L_{\mathrm
p}(\theta)=\mathcal L_{\mathrm{act}}(\theta;\mathcal D_{\mathrm{mix}}^{\mathrm{pre}})$. The mixture
$\mathcal D_{\mathrm{mix}}=\alpha\mathcal D_{\mathrm{task}}+(1-\alpha)\mathcal D_{\mathrm{local}}$
samples original-task and local supervision, respectively. Local commands and visual prompts teach
scene-dependent control, while original-task examples retain complete-task supervision. The
resulting checkpoint is SmartVLA-Base.

\textbf{Adaptation: retain both supervision granularities.} Original-task instructions alone do not
preserve local command--action supervision, while local segments cannot replace supervision of
complete execution. We therefore reconstruct target-domain demonstrations using
Section~\ref{steering-oriented-data-construction} and independently adapt each domain $d$ from
SmartVLA-Base, optimizing both modules with $\mathcal L_{\mathrm a}^{d}(\theta)=\mathcal
L_{\mathrm{act}}(\theta;\mathcal D_{\mathrm{mix}}^{d})$. This continues local language and visual
supervision while learning target-domain control.

SmartVLA-Pi and SmartVLA-OFT follow this recipe with their native action models. Both accept
complete-task, subtask, or updated corrective commands through the same observation-conditioned
interface. Architectures, initialization, sampling ratios, training settings, and the calling
protocol are detailed in Appendix~\ref{appendix:model-details}.
